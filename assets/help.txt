lowpass-variants-nextflow
=========================

Unified low-pass per-sample SNV/indel workflow for fresh or FFPE material.

ENTRY POINT
  ./bin/run_pipeline.sh [Nextflow options] [pipeline parameters]

  The launcher auto-detects Nextflow syntax parser v2 or v1. Direct
  nextflow run main.nf usage bypasses that detection.

NEXTFLOW RUN CONTROLS
  -profile conda                Use the supplied Conda dependency profile.
  -profile docker               Run tasks in the versioned pipeline image;
                                requires a local Docker daemon.
  -work-dir DIR                 Optional. Choose a persistent Nextflow work
                                directory; otherwise Nextflow uses its default.
  -resume                       Optional. Reuse completed tasks from the same
                                work directory on a rerun.

  Keep the same work directory when using -resume. Production examples include
  both optional controls so interrupted runs can reuse completed work.

DOCKER IMAGE
  The docker profile uses:
    ghcr.io/cfarkas/lowpass-variants-nextflow:1.0.0

  Install it with:
    docker pull ghcr.io/cfarkas/lowpass-variants-nextflow:1.0.0

  Before that tag is available, build it locally with:
    docker build -t ghcr.io/cfarkas/lowpass-variants-nextflow:1.0.0 .

  Host python3 is required for input discovery. Bundled Docker checks:
    NEXTFLOW_PROFILE=docker bash examples/run_minimal_fresh.sh
    NEXTFLOW_PROFILE=docker bash examples/run_minimal_ffpe.sh

REQUIRED MODE (choose exactly one)
  --fresh                       Common calling + BQSR by default + left alignment.
                                Performs no FFPE assessment: no FFPE-specific
                                thresholds, heuristic, FFPErase run, TSV
                                columns, or VCF INFO fields.
  --ffpe                        Common workflow + FFPE heuristic + external
                                FFPErase classification and VCF annotation.

  Both flags together, or neither flag, are rejected.

REQUIRED INPUTS
  --input PATH                  BAM directory, BAM, manifest, or BAM list.
  --outdir PATH                 Output directory.
  --ref FASTA                   Reference FASTA; copied into task work.
  --known_sites VCF1,VCF2      Comma-separated BQSR known-sites VCFs.
                                Required unless --skip_bqsr is used.
                                Compressed: adjacent .tbi/.csi/.idx;
                                uncompressed: adjacent .idx.
  --skip_bqsr                   Explicitly disable BQSR.

INPUT STAGING AND SAFETY
  BAMs, reference, known-sites, and optional Mutect2 resources are staged.
  Reference sidecars and missing BAM indices are created in task work; source
  directories are not modified. Resource basenames must be unique per set.
  --germline_resource/--panel_of_normals require adjacent .tbi/.csi/.idx.

OUTPUT CONTROL
  --overwrite true|false        Replace published products; default: false.
                                nextflow_info metadata is refreshed separately.

SELECTION AND SCOPE
  --samples CSV                 Comma-separated sample IDs.
  --recursive                   Search recursively below --input.
  --genes CSV                   Restrict to selected gene symbols.
  --bed BED                     Restrict to a BED file.
  --target_bed BED              Alias for --bed.

FFPE-ONLY CONTROLS
  --ffperase_threads N
  --ffperase_classify_threads N
  --ffperase_sample_jobs N
  --ffperase_picard_jobs N
  --ffperase_split_pileup N
  --ffperase_split_reads N
  --ffperase_container PATH_OR_URI
  --ffperase_engine auto|apptainer|singularity|docker
  --ffperase_repository REPO
  --ffperase_revision REVISION
  --ffperase_filter_artifacts true|false
  --ffperase_fail_on_error true|false

NORMALIZATION
  Both modes left-align every caller VCF and final VCF with bcftools norm
  against --ref. Normalization/indexing errors fail the workflow. Every
  normalized compressed VCF requires a .tbi; TBI-incompatible data fail.

MINIMAL REAL-DATA EXAMPLES: BQSR
  Fresh:
  ./bin/run_pipeline.sh \
    -profile conda \
    --fresh \
    --input /path/to/SAMPLE.bam \
    --outdir /path/to/fresh-results \
    --ref /path/to/reference.fa \
    --known_sites /path/to/dbsnp.vcf.gz,/path/to/known_indels.vcf.gz

  FFPE:
  ./bin/run_pipeline.sh \
    -profile conda \
    --ffpe \
    --input /path/to/SAMPLE.bam \
    --outdir /path/to/ffpe-results \
    --ref /path/to/reference.fa \
    --known_sites /path/to/dbsnp.vcf.gz,/path/to/known_indels.vcf.gz

  --samples is optional. Without it, all BAMs resolved from --input are used.
  For a deliberate no-BQSR run, replace --known_sites with --skip_bqsr.

MINIMAL DOCKER REAL-DATA EXAMPLES: BQSR
  Fresh:
  ./bin/run_pipeline.sh \
    -profile docker \
    --fresh \
    --input /path/to/SAMPLE.bam \
    --outdir /path/to/fresh-results \
    --ref /path/to/reference.fa \
    --known_sites /path/to/dbsnp.vcf.gz,/path/to/known_indels.vcf.gz

  FFPE:
  ./bin/run_pipeline.sh \
    -profile docker \
    --ffpe \
    --input /path/to/SAMPLE.bam \
    --outdir /path/to/ffpe-results \
    --ref /path/to/reference.fa \
    --known_sites /path/to/dbsnp.vcf.gz,/path/to/known_indels.vcf.gz

  Use absolute host paths. FFPE Docker mode mounts the local daemon socket into
  its orchestration task. This is privileged-equivalent host access. Its
  upstream workflow, runtime image, and models are fetched separately when
  needed unless cached.

BUNDLED SYNTHETIC SMOKE EXAMPLES
  bash examples/run_minimal_fresh.sh
  bash examples/run_minimal_ffpe.sh

  Inputs and indexes are included under examples/tiny/. The fresh quickstart
  runs BQSR plus FreeBayes and BCFtools, producing exactly chr1:25 A>C with two
  votes. The FFPE check runs BQSR but skips all callers, producing a header-only
  VCF; it checks empty-variant handling, not non-empty model classification.
